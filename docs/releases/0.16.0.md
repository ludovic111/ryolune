# ryolune 0.16.0

An agent that knows music and checks its work. Whichever agent you use (ryolune's own, Claude
Code, Codex or the lsuite app's), it now works like a producer: it plans, follows a playbook for
the job, looks at and listens to what it made, measures the loudness, fixes what is off, and only
then says it is done. And one button takes back everything it did in a turn.

## A producer's brief and playbooks

- **One brief for every agent**: the music producer's role, how a ryolune song is built, the
  commands for each job, the quality bar (parts in key and in their register, grooves with
  dynamics, levels with headroom, loudness for streaming, club, broadcast or podcast) and the
  finish routine. The built-in agent and ryolune's MCP server send the same text.
- **13 skills**, playbooks the agent loads for the job at hand: compose from a brief, drums,
  bass and chords, melody and hooks, arrangement, sound design, automation, mixing, mastering to
  a loudness target, export and stems, scoring a kimchi cut, writing a plugin, and reviewing a
  song. Each lists its steps, the exact commands and the checks that prove the job worked.
  Outside agents get them as MCP prompts and resources too.

## Eyes and ears

- **The agent sees what it made.** `harness.look` renders a bar range and draws it: the
  waveform with the bars and sections (clipping in red), the loudness over time, the spectrum,
  and a piano roll of the notes in each track's colour. Agents whose model reads images see the
  picture itself; the numbers come with it.
- **And measures it**: integrated, short-term and momentary loudness (LUFS, EBU R128), loudness
  range, true peak (dBTP), clipping, and the energy from sub to air, for the mix or each track,
  with findings that say what to fix ("1.8 LU under the -14 LUFS target: raise the Limiter's
  input by about 2 dB").
- **It knows what you changed.** Before each step the built-in agent reads the song in brief and
  what you did meanwhile, and keeps your changes.

## One undo per turn

- Every turn of the built-in agent starts with a checkpoint. When it ends, the chat and the
  Changes tab list what it changed in plain words, with **Revert turn**: one step back to how the
  song was, and Redo turn to bring it back. `agent.revertTurn` does the same from a script.
- Any agent can do it: `harness.checkpoint`, `harness.changes`, `harness.revert`. ryolune's MCP
  server takes a checkpoint before an outside agent's first edit, and until the agent has
  looked or measured, each edit's result reminds it of the finish routine.

## Updates through lsuite

- ryolune now updates through lsuite: the app asks lsuite.xyz for the latest version with your
  free lsuite account, and still checks every download against ryolune's signature before it
  replaces anything. Signed out, Settings › Updates says to sign in to lsuite (in the lsuite
  app) instead of showing an error. Builds of new versions come through the lsuite app.

## For developers

- New commands: `harness.brief`, `harness.skills`, `harness.skill`, `harness.context`,
  `harness.look`, `harness.measure`, `harness.checkpoint`, `harness.checkpoints`,
  `harness.changes`, `harness.revert`, `agent.revertTurn`. `docs/HARNESS.md` is the brief and
  every skill, generated from the source.
- `evals/`: 13 scripted music jobs run headless through Claude Code and `ryolune-mcp`, scored on
  the resulting song; results in `evals/RESULTS.md`.
- Releases are drafts; `scripts/publish-build.sh <version>` publishes one to lsuite.
